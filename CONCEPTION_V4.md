# CONCEPTION V4 — vêtements amples et simulation de tissu (documentation et mesures AVANT implémentation)

Date : 2026-11-24. Statut : **aucune implémentation** ; ce document rapporte (1) ce que la documentation de Blender 5.2 dit, source par source (D-35 : « non vérifié » quand rien n'a été lu), (2) des mesures faites dans ce projet, (3) les options et une recommandation. Scripts de mesure : `tools/measure_cloth.py` (Cloth classique) et `tools/measure_cloth_gn.py` (Cloth Dynamics natif 5.2).

## 1. Ce que dit la documentation (sources lues)
Manuel utilisateur 5.2 fourni avec Blender (recherche plein texte locale, fichiers `manual/…`), sauf mention contraire.

**Cloth classique (modificateur « Cloth », solveur historique)**
- Le modificateur Cloth est un conteneur ; les options sont dans l'onglet Physique (`manual/modeling/modifiers/physics/cloth.rst`). Sa position dans la pile compte : le tissu est calculé « en accord avec l'ordre de la pile » ; on lisse **après** (`manual/physics/cloth/introduction.rst`).
- Quatre types de ressorts : tension, compression, cisaillement, flexion angulaire, réglables séparément (`manual/physics/cloth/introduction.rst`, `…/settings/physical_properties.rst`). Masse du sommet, viscosité de l'air, modèle de flexion (`physical_properties.rst`). Ressorts internes et pression : réservés aux maillages 3D / fermés (`physical_properties.rst`).
- **Qualité (Quality Steps)** : nombre de pas de simulation par image ; plus haut = meilleure qualité, plus lent (`manual/physics/cloth/settings/index.rst`). Speed Multiplier : vitesse du temps de simulation (même page).
- **Collisions** (`…/settings/collisions.rst`) : Quality (finesse ; plus haut = moins de déchirures et de pénétrations, plus lent), Object Collisions (l'objet qui dévie le tissu doit avoir la physique de collision), Distance (distance à laquelle un objet repousse le tissu : « trop petite = erreurs mais plus rapide ; trop grande = irréaliste et lent »), Impulse Clamping (empêche les explosions dans les collisions serrées), Collision Collection, Vertex Group d'exclusion ; Self-Collisions (« ajoute au temps de calcul » mais plus réaliste ; utile en gros plan), friction propre, distance propre. Dépannage officiel : augmenter la distance (rapide mais « tissu qui repose sur de l'air »), augmenter la qualité et la qualité de collision, éditer le résultat caché ; « si le tissu est déchiré par le maillage qui se déforme, augmenter les raideurs ».
- **Collision** (`manual/physics/collision.rst`) : « Le Collision Modifier doit être **après** » les clés de forme et armatures (le tissu doit recevoir la vraie forme du maillage à cette image) ; épaisseur (Thickness) extérieure/intérieure.
- **Épinglage** (`…/settings/shape.rst`) : groupe de sommets d'épinglage (poids = force), raideur de la cible ; **Dynamic Mesh** : forme de repos recalculée à chaque image à partir des modificateurs placés au-dessus (armature, clés de forme).
- **Interaction avec l'armature** (`manual/physics/cloth/examples.rst`, « Cloth on Armature ») : armature en pose de repos ; vêtement qui entoure sans pénétrer ; vêtement enfant de l'armature ; groupe de sommets d'épinglage (poids 1, ex. ceinture) ; **le modificateur Cloth sous le modificateur Armature** ; collision activée sur le corps ; les sommets épinglés restent sous le contrôle de l'armature, les autres sous celui du Cloth.
- **Cache et bake** (`manual/physics/cloth/settings/cache.rst`) : choisir début/fin puis « Bake » ; les paramètres de cache sont ceux des autres systèmes dynamiques (cache de particules) ; **si l'on déplace ou édite l'objet après la simulation, il faut vider le cache** ; début/fin ne se changent pas sans vider le bake ; l'édition du cache est **signalée comme non fonctionnelle** (ticket blender#77114, d'après la page).
- Champs de force : panneau Field Weights (`…/settings/field_weights.rst`) ; non lu en détail.

**Nouveautés 5.x (notes de version officielles, lues par un sous-agent via résumé : formulations paraphrasées, À VÉRIFIER sur la page avant citation exacte)**
- 5.0 (`developer.blender.org/docs/release_notes/5.0/physics/`) : les caches de points compressés LZO/LZMA ne sont plus lus (remplacés par ZSTD, compression toujours active, nouveaux caches plus petits et plus rapides) ; les anciens caches sont à supprimer et recalculer.
- 5.1 : rien trouvé sur le tissu (page physique 404).
- **5.2 — CITATIONS EXACTES** (page `https://developer.blender.org/docs/release_notes/5.2/physics/`, texte original relu, section « Blender 5.2 LTS: Physics » puis « Cloth Dynamics », « Effectors », « Colliders », « XPBD Solver ») : « There are new _experimental_ Geometry Nodes based physics systems for hair and cloth. » ; « They are experimental in this release because it's hard to lock in the design without more widespread testing first. » ; « The new experimental **Cloth Dynamics** modifier and node group can just be added to any mesh to give it cloth-like behavior. » ; « The Hair and Cloth Dynamics groups have a bunch of built-in effectors for ease-of-use like gravity and surface collision. » ; « **Collider**: Any _closed_ mesh can be used as collider. » ; « A collider object is created by adding a **Collider** modifier to it. » ; « This uses the geometry at that point in the modifier stack as collision mesh. » ; « The Cloth and Hair Dynamics assets are internally powered by a new built-in XPBD Solver node. » ; « It does the heavy lifting solving various constraint types. » (La page ne mentionne aucun cache de points.) Note : « Any closed mesh can be used as collider » : notre corps est un maillage fermé (non vérifié pour les mains et la bouche).
- Résumé précédent des notes 5.2 (paraphrase) : nouveau modificateur / groupe de nœuds **« Cloth Dynamics » (expérimental)**, pour tout maillage ; épinglage, élasticité, flexion, déchirure ; solveur **XPBD** ; **modificateur « Collider »** (la géométrie utilisée est celle présente à ce point de la pile) ; filtres par étiquettes ; « les nouveaux systèmes physiques basés sur les nœuds géométriques, pour les cheveux et le tissu, sont expérimentaux et pourraient encore changer de design ». Aucune donnée de performance chiffrée.
- **Non vérifié** : le manuel 5.2 local ne contient AUCUNE page sur « Cloth Dynamics » ni sur XPBD (recherches « Cloth Dynamics », « XPBD » : sans résultat) ; ce que nous savons de ses entrées vient du groupe de nœuds lui-même (fichier d'assets `geometry_nodes_dynamics_assets.blend`, descriptions des sockets : Pin Group, Invert Pin Group, Stretchiness, Bendiness, Substeps, Constraint Steps, Mass, Friction, Collision Radius, Linear Damping, Gravity, Tearing…, Effectors Collection, Cloth Tags ; et pour « Collider » : Deforming, Boundary, Margin, Friction, Softness, Filter, Error Threshold). L'interaction avec le cache de simulation passe par les nœuds de simulation (bake des modificateurs de nœuds géométriques : `bpy.ops.object.simulation_nodes_cache_bake`, API 5.2).

> **CORRECTION (voir §7)** : les profondeurs de pénétration de ce tableau (28–37 mm) étaient dues à deux défauts de mon montage, découverts à l'implémentation : (1) le modificateur « Collider » du corps était laissé à « Deforming = faux » alors que le corps est animé (description du socket : « Whether the collider geometry is changing. ») ; (2) le bras était tourné dans le mauvais sens (vers l'intérieur au lieu de lever). Les valeurs de coût, de stabilité, de reproductibilité et de cache restent valables ; les profondeurs de pénétration du tableau NE le sont PAS (refaites en §7). Les lignes du Cloth classique n'ont pas été refaites (sens du bras non vérifié) : leurs pénétrations ne sont pas comparables.

## 2. Mesures faites ici (scénario : veste procédurale V1 à 30 mm de décalage, 2 117 sommets, 174 épinglés aux épaules, bras gauche levé à 80° + torsion de la colonne sur 40 images, Windows, machine de développement)

| natif, rayon 4 mm | 50 ms | non | 1,09 % | 32,2 mm | oui | 2,0 s |

- **Reproductibilité** : deux simulations successives depuis la première image donnent des positions identiques bit à bit (les deux solveurs). **Relecture après enregistrement et réouverture** : écart 0,0 m aux images 10, 20, 40 pour le cache classique (cache dans le .blend) et pour le cache natif (cible « emballé » `PACKED`, plage d'images imposée) ; relecture de 3 images : 0,06 s. Sans régler la cible et la plage du cache natif (valeurs par défaut `INHERIT`, 1 à 100), l'opérateur de bake n'a rien produit de rejouable dans mon premier essai : à fixer dans l'implémentation.
- **Pénétration** : aucun réglage n'élimine la pénétration profonde (≥ 28 mm) : elle se situe sous l'aisselle quand le bras monte, là où le corps s'auto-intersecte déjà (voir `CONCEPTION_V1.md`, V-2). Une part de sommets pénétrants plus faible n'implique pas une profondeur plus faible. L'auto-collision du Cloth classique a **dégradé** la pénétration dans ce scénario (12,7 % contre 1,9 %) : cause non investiguée (non vérifié).
- **Stabilité** : aucune explosion ni valeur non finie dans les 10 essais (déplacement maximal par image 2,4 à 17 cm). Limite : un seul scénario (veste, 40 images) ; pas de test de robe, de jupe ni de mouvement rapide (course).

## 3. Compatibilité avec la foule (150 personnages)
- Coût de simulation mesuré : 41–62 ms par image et par vêtement (natif, 1,1–2,1 k sommets) ; 84–260 ms (classique). Pour 150 personnages avec un vêtement chacun : de l'ordre de **6 à 9 s par image** de simulation, plus le corps. **Pas réalisable en simulation directe.**
- La lecture d'un cache cuit est rapide (0,06 s pour 3 images ≈ le coût d'évaluation du corps et de la pièce), mais le cuisson de 150 vêtements sur 720 images représente (natif, 2,1 s / 40 images pour une pièce de 2,1 k sommets) environ 38 s par pièce soit **près de 1 h 30** pour 150 pièces, et un cache à stocker (non mesuré : taille du cache sur 720 images non mesurée ; le .blend de 40 images pèse environ 22 Mo avec le corps).
- **Recommandation foule** : pas de simulation. Pièces ajustées sans simulation (V1/V2), éventuellement avec un décalage plus ample et des « formes d'aisance » statiques par pièce.

## 4. Options
- **A. Cloth Dynamics natif 5.2** (recommandé pour les personnages de premier plan) : plus rapide que le Cloth classique à qualité comparable (62 ms contre 84 ms à qualité 5, et pénétration 0,94 % contre 1,9 %), reproductible, bake rejouable ; MAIS marqué « expérimental » par Blender (le design peut changer), pas de documentation dans le manuel local, pas d'auto-collision documentée. Cohérent avec le groom natif déjà utilisé (XPBD).
- **B. Cloth classique** : documenté, stable, auto-collision disponible mais lente et ici défavorable ; qualité 10 : 152 ms par pièce.
- **C. Sans simulation** (foule) : pièces ajustées V1/V2 ; l'ampleur est obtenue par un décalage plus grand et des formes d'aisance ; aucun mouvement du tissu.
- **Géométrie à ajouter** : les pièces V1 sont des sous-maillages COLLÉS au corps ; une simulation sur un vêtement collé n'ajoute rien. Pour des vêtements amples (robe, jupe, manteau long, cape) il faut de nouvelles géométries de base (par exemple jupe = anneau de la taille étendu vers le bas, manteau long = pièce V1 prolongée sur les cuisses avec plus de sommets) : **non conçues ni testées**.

## 7. Corrections et réalisation (V4, 24 nov. 2026)
**Décisions de l'utilisateur** : (1) Cloth Dynamics natif 5.2 pour les personnages de premier plan (expérimental accepté ; XPBD et Cloth Dynamics restent « non vérifiés » dans le manuel local : seules les notes de version 5.2, citées mot pour mot au §1, les décrivent) ; (2) pièces amples = robes (robe longue, mi-longue, courte ; jupe) ; (3) seuil de pénétration sous l'aisselle : 15 mm en gros plan ; (4) foule : pièces ajustées V1/V2 sans simulation.

**Réalisation** : `extension/garments.py` (4 nouvelles pièces « Robes » : corsage = sous-maillage du corps sans manches, jupe = 23 anneaux de 48 sommets construits autour du corps depuis la taille jusqu'à l'ourlet, ellipse enveloppant les deux jambes + aisance qui croît vers l'ourlet, garde-fou : aucun sommet de jupe à moins de 4 mm du corps au repos ; poids du sommet du corps le plus proche ; groupe d'épinglage : corsage 1, anneaux 0/1/2 de la jupe = 1 / 0,6 / 0,2) ; `extension/cloth_sim.py` (activation, cache emballé à plage fixée, vidage, coût) ; `extension/cloth_ui.py` (panneau « Tissu (robes) ») ; `tools/validate_cloth_sim.py` (S1–S5) ; planche `tools/render_dress_board.py` + `assemble_dress_board.py`.

**Mesures corrigées du scénario veste (2 117 sommets, Collider « Deforming » vrai, bras levé dans le bon sens, 40 images)** : natif pas 5 / contraintes 15 : 67 ms par image, profondeur de pénétration max **8,1 mm** (0,33 % des sommets) ; T-shirt (1 124 sommets) : 54 ms, 0 mm ; pas 10 / contraintes 30 : 134 ms, 9,3 mm ; stabilité sans explosion ; reproductibilité bit à bit ; relecture du cache emballé identique.

**Mesures des robes (`validate_cloth_sim`, robe mi-longue, 3 morphologies × 3 mouvements de 40 images : marche à ±35° de hanche avec genou fléchi, bras levés à 80° avec torsion de la colonne, torsion du buste)** : aucune explosion (pas maximal par image 0,25 m en marche) ; **pénétration maximale : jupe 9,5 mm (marche), corsage 7,6 mm (torsion)** ; dans le cas « aisselle » (bras levés) le corsage pénètre au plus 2,2 mm : le seuil de 15 mm est respecté ; coût ≈ 62 ms par image (≈ 1 780 sommets) ; cuisson de 40 images 2,8 s ; relecture de 3 images 0,06 s ; reproductibilité bit à bit ; cache emballé rejoué à l'identique après enregistrement et réouverture (écart 0,0 m) ; .blend ≈ 23 Mo.

**Leçons de mise au point (à ne pas refaire)** : sans « Deforming » le tissu traverse le corps qui bouge (jupe : 40–54 mm en marche) ; une aisance trop faible à la taille oblige les cuisses à pousser le tissu : jupe construite avec 30 mm d'aisance dès la taille ; le sens de rotation qui lève un bras doit être mesuré (pas supposé).

**Limites connues** : fonctionnalité expérimentale de Blender (le design peut changer) ; pas d'auto-collision (non documentée pour le groupe natif) ; la jupe est un tube évasé simple (pas de plis dessinés, ourlet net) ; corsage collé au corps (épinglé) : seule la jupe bouge ; robes testées sur 3 morphologies et 3 mouvements lents ou modérés (pas de course ni de saut) ; le tissu natif ne tient pas compte des mains/doigts comme colliders (non vérifié) ; une robe est reconstruite (non ajustée) quand la morphologie change et la simulation doit être recuite ; jamais pour la foule (≈ 60 ms par pièce et par image).
